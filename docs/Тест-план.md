# Тест-план
## для модульного тестирования "Candy Delivery API"

### 1. Введение
**1.1. Цель:** Обеспечить контроль качества backend-части системы, проверить корректность бизнес-логики, валидации данных и безопасность эндпоинтов.

**1.2. Объект тестирования:** REST API веб-сервиса на фреймворке FastAPI (эндпоинты `/api/login`, `/couriers`, `/orders`, `/orders/assign`, `/orders/complete`, а также эндпоинты отмены и удаления заказов).

### 2. Стратегия тестирования
**Модульное (интеграционное) тестирование API:** Автоматизированная проверка HTTP-методов с использованием фреймворка `pytest` и библиотеки `requests`. Проверка как позитивных сценариев (HTTP 200/201), так и негативных (HTTP 400, 401, 404), включая обязательное регрессионное тестирование ранее выявленных дефектов.

### 3. План модульного тестирования (API)
Тесты расположены в директории `backend/tests/`.

| № | Тестируемый эндпоинт | Сценарий | Ожидаемый результат |
|---|---|---|---|
| 1 | `POST /api/login` | Успешный вход администратора | Статус 200, наличие `access_token` и `role` |
| 2 | `POST /api/login` | Успешный вход курьера | Статус 200, наличие `access_token`, `role` и `courier_id` |
| 3 | `POST /api/login` | Неверный пароль или несуществующий пользователь | Статус 401, сообщение об ошибке |
| 4 | `GET /couriers` | Получение полного списка курьеров | Статус 200, корректный список объектов |
| 5 | `POST /couriers` | Импорт валидных данных курьеров | Статус 201, возврат списка ID |
| 6 | `POST /couriers` | Импорт невалидных данных (отрицательный ID, неверный тип) | Статус 400, описание ошибки валидации |
| 7 | `GET /couriers/{id}` | Получение данных существующего курьера | Статус 200, корректные поля (включая рейтинг и заработок) |
| 8 | `GET /couriers/{id}` | Запрос несуществующего курьера | Статус 404 |
| 9 | `PATCH /couriers/{id}` | Обновление данных курьера | Статус 200, обновленные данные |
| 10| `GET /couriers/{id}/orders` | Получение списка заказов конкретного курьера | Статус 200, корректный список заказов |
| 11| `GET /orders` | Получение полного списка заказов администратором | Статус 200, корректный список объектов |
| 12| `POST /orders` | Импорт валидных данных заказов | Статус 201, возврат списка ID |
| 13| `POST /orders` | Импорт невалидных данных заказа (отрицательный вес/ID) | Статус 400, описание ошибки валидации |
| 14| `POST /orders/assign` | Назначение заказов доступному курьеру | Статус 200, список назначенных ID |
| 15| `POST /orders/complete` | Попытка завершить чужой или несуществующий заказ | Статус 400 |
| 16| `PATCH /orders/{id}/cancel` | Попытка отменить несуществующий заказ | Статус 404 |
| 17| `DELETE /orders/{id}` | Попытка удалить несуществующий заказ | Статус 404 |

### 4. Критерии начала и окончания тестирования
- **Начало:** Реализованы все эндпоинты API, настроена тестовая база данных PostgreSQL, файл `.env` сконфигурирован.
- **Окончание:** 100% тестов из набора `pytest` проходят успешно (статус PASSED), критические баги, выявленные при тестировании, исправлены и подтверждены регрессионными тестами.
