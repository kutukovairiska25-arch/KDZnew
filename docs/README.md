## Архитектура и структура проекта (Backend)

Проект построен по принципу разделения ответственности (Separation of Concerns). Ниже приведено описание ключевых модулей:

### Конфигурация и инициализация
- **`main.py`** — Главная точка входа в приложение. Инициализирует экземпляр FastAPI, настраивает CORS для взаимодействия с фронтендом, подключает роутеры и при запуске создает таблицы в БД и тестовых пользователей.
- **`config.py`** — Управляет настройками приложения. Читает переменные окружения (хост, порт, пароли, секретные ключи) из файла `.env` с помощью библиотеки `dotenv`.
- **`database.py`** — Содержит конфигурацию SQLAlchemy: создание двигателя (engine), фабрики сессий (`SessionLocal`) и базового класса для ORM-моделей (`Base`).

### Работа с данными
- **`models.py`** — Описание ORM-моделей SQLAlchemy, которые маппятся на таблицы PostgreSQL (`User`, `Courier`, `Order`). Определяет типы данных, первичные и внешние ключи.
- **`schemas.py`** — Схемы валидации Pydantic. Описывают структуру ожидаемых JSON-запросов и формат ответов. Содержат кастомные валидаторы (например, строгая проверка формата времени работы курьера 07:00–22:00 и пересечения интервалов доставки).
- **`crud.py`** — Слой доступа к данным (CRUD-операции). Изолирует прямые запросы к базе данных от маршрутов, обеспечивая чистоту кода и переиспользование логики (Create, Read, Update, Delete).

### Бизнес-логика и маршрутизация
- **`utils.py`** — Модуль с чистой бизнес-логикой, не зависящей от фреймворка. Содержит функции для расчета рейтинга курьера, подсчета заработка с учетом коэффициентов и проверки пересечения временных интервалов.
- **`auth.py`**, **`couriers.py`**, **`orders.py`** — Роутеры (маршрутизаторы) FastAPI. Описывают HTTP-эндпоинты, принимают запросы, вызывают функции из `crud.py` и `utils.py`, и возвращают ответы.
- **`createDbUsers.py`** — Скрипт для инициализации среды разработки. Сбрасывает и пересоздает таблицы, заполняя их тестовыми данными (1 администратор, 3 курьера с разными типами транспорта, 10 тестовых заказов).

### Тестирование
- **`conftest.py`** — Конфигурация pytest. Содержит фикстуры для получения JWT-токенов администратора и курьера, которые переиспользуются во всех тестах.
- **`test_auth.py`**, **`test_couriers.py`**, **`test_orders.py`** — Набор интеграционных тестов, покрывающих основные сценарии API (позитивные и негативные кейсы, включая проверку исправленных багов валидации и сериализации).

## Функционал системы

### Роль "Администратор"
- Авторизация в системе.
- Массовый импорт данных курьеров и заказов через JSON.
- Просмотр полного списка курьеров и заказов.
- Редактирование данных курьера (тип транспорта, регионы, часы работы) с автоматическим сбросом неактуальных назначенных заказов.
- Отмена назначенного заказа и удаление заказа из системы.

### Роль "Курьер"
- Авторизация и просмотр личного профиля с динамически рассчитываемыми метриками (рейтинг, заработок).
- Запрос на получение новых заказов (система автоматически подбирает заказы с учетом грузоподъемности, совпадения регионов и пересечения графиков работы).
- Отметка о выполнении заказа с фиксацией времени.
- Просмотр статистики выполненных и отмененных заказов.

### Системная бизнес-логика
- **Распределение:** Учет грузоподъемности (пеший: 10 кг, вело: 15 кг, авто: 50 кг).
- **Расчет рейтинга:** На основе среднего времени доставки по районам.
- **Расчет заработка:** Фиксация типа курьера на момент назначения заказа для честного расчета коэффициента оплаты, даже если тип курьера был изменен администратором позже.
